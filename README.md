# Archive Flow

一个运行在本机或自托管主机上的 Bilibili 合集自动备份工作台。Node.js + TypeScript 服务端，React 界面，TOML 保存可迁移的项目配置，SQLite 保存快照和运行记录；下载由固定版本的官方 yt-dlp 独立二进制执行。新系统不依赖 Python。

最初的 Python CLI、配置、说明和 8 项原测试保存在 `legacy/`，仅作备份参考。临时 Python server 和第一版界面已删除，新服务没有调用旧 CLI。

## 启动

需要 Node.js 24、npm，以及下载/校验时使用的 ffmpeg 和 ffprobe。Windows、macOS 使用相同的项目命令：

```sh
npm ci
npm run setup:downloader
npm run setup:storage
npm run build
npm start
```

打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。安装脚本从官方 release 下载对应系统的独立二进制，并校验 SHA-256。当前固定 yt-dlp `2026.08.19`；不会自动更新或切换到系统中其他版本。

云存储使用项目附带的 rclone `1.75.1`（`bin/rclone/`），通过开源 [rclone-sdk](https://github.com/rclone-ui/rclone-sdk) 调用 RC API；不查找 PATH，不使用系统 rclone。构建与 `npm start` 会检查并准备对应平台的二进制；安装后离线也能启动。Windows、macOS、Linux 的 x64/arm64 都有对应官方包。二进制下载校验 SHA-256，保留校验清单与官方 README；不提交到 Git，发布时需包含 `bin/rclone/`。

`npm run bundle` 在 `.qa/` 生成 `archive-flow-0.2.0.tgz`，包含本平台 rclone、构建产物、源码和使用说明，排除运行数据库、账号配置和依赖目录。解压后先运行 `npm ci`，再运行 `npm start`；附带二进制已校验时不会再下载。不同平台分别构建分发包，包内 manifest 记录实际平台；换平台部署时安装脚本会替换为目标平台版本。

ffmpeg / ffprobe 可放在 PATH 中，或在「全局设置」填写绝对路径。只打开界面、查看缓存不需要这些媒体工具。

已有安装在首次启动新版时，将 SQLite 中的项目配置迁移到 `state/config.toml`，保留 ID、关联、排除规则、计划间隔和运行记录。迁移成功后数据库不再保存项目配置；之后以 TOML 为准。缺少托管 Cookie 文件或配置无效时停止迁移，保留原数据库。

全新安装且没有项目配置时，自动导入 `legacy/config.toml` 的配置和 Cookie 文件引用，保留原下载路径，关闭所有自动计划。已有 TOML 时不会再导入 legacy，即使运行数据库是空的。

## 使用

1. 在「Cookie 管理」添加或更新凭据实例，点击「验证登录态」。支持导入 Netscape 文件并由本机托管、引用你维护的文件、直接读取服务电脑上的浏览器。
2. 在「存储管理」添加命名存储源（本地目录或云存储），点击「检查连接」。新建或编辑备份配置时选择存储源名字、Cookie 实例，可设置独立下载目录和日期下限。
3. 打开配置，点击「刷新列表」。刷新在后台进行，只读合集清单与存储文件索引，不逐条查询视频画质；云端失败保留旧快照，避免把断网当成文件缺失。
4. 在 diff 中搜索、筛选、勾选或排除条目。也可通过「维护排除项」逐行添加 BV。BV 主体保留原大小写。
5. 点击下载。未勾选时处理所有待下载/需核验的中转文件；勾选后只处理所选条目。任务记录显示进度、失败原因，并支持取消排队中或执行中的任务。

| diff 状态 | 含义 |
| --- | --- |
| 待下载 | 来源中存在，本地存档与下载目录未找到同 BV 成品 |
| 已存档 | 存档目录中有同 BV 媒体文件；仅比对文件名，不重新验画质 |
| 下载目录已有 | 下载目录发现同 BV；执行时仍会按当前最高格式核验尺寸 |
| 已排除 | 手动排除，刷新和自动任务都继续遵守 |
| 日期过滤 | 发布日期不晚于配置下限，不下载 |
| 源中移除 | 上次清单有、本次清单没有；不会删除本地文件 |

合集清单缺少日期时显示「下载时核验」，不会假装已经满足日期条件。刷新失败保留旧快照及其原始时间；任务明确显示失败。修改来源、Cookie、日期或路径后会使旧 diff 失效，需要重新刷新。

## 自动执行

配置中的检查间隔为 `0` 时手动执行；自动间隔至少 5 分钟。

- 仅开启间隔：按时刷新 diff，等待人工审核。
- 同时勾选「自动检查成功后下载」：刷新成功后继续下载，遵守日期和排除项。
- 服务关闭或电脑休眠期间不执行；重启后到期计划只补一次检查，不补发积压的每个时点。
- 同一配置不重复排队。任务全局串行运行；网络和 yt-dlp 子进程异步执行，页面可继续操作。
- 取消会停止当前子进程；保留已有文件和 `.part`。失败条目可重试。重启将旧的排队/执行任务标为「已中断」，不会未经审核直接恢复旧下载。

关闭浏览器不影响自动计划，关闭 Node.js 服务会停止计划。当前版本不自动安装系统开机服务；需要持续自动备份时，请让服务随你自己的 Windows 任务计划、launchd 或进程管理器运行。

## 目录规则

`download_dir` 是可选的本地中转目录，用于下载、合并、校验和云端取回；最终存档位置由存储源决定。`settings.download_root` 同样可省略或留空，默认 `~/Downloads/ArchiveFlow`。未指定独立中转目录的配置使用：

```text
统一下载根目录/
  配置名称/
    [YYYY-MM-DD] 标题 [BVxxxxxxxxxx].mp4
```

配置名会转换为 Windows/macOS 可用的文件夹名，命名冲突会拒绝保存。独立下载目录优先于统一根目录。改名或改路径不会搬迁旧文件。页面可复制路径或打开目录；「打开目录」打开的是服务主机上的文件管理器。

存储源与本地下载目录独立。已有媒体按文件名中的 BV 索引，忽略 `.part`、侧录 JSON 和未合并的格式分片。不会删除源中移除的文件，也不会自动把新下载搬入存储源；通过「存档所选」或条目菜单存档。

「编辑备份配置 → 存档目录结构」控制最终存档位置，TOML 字段为 `directory_template`。支持平铺（省略或空字符串）、`{{YYYY}}/{{MM}}/`、`{{YYYY}}-{{MM}}/`、`{{YYYY}}/`，例如视频发布日期为 2026-08-01，第一种年月格式会存入「存储源根目录 / 2026 / 08 / 原文件名」。本地与云存储使用同样规则，中转目录保持原规则。日期优先取当前清单、下载凭证，旧视频可从标准文件名前缀 `[YYYY-MM-DD]` 获取；无法确定日期时放在存储源根目录，不用操作当天日期替代。改变目录结构不会移动已有文件或清除列表快照，扫描及同名冲突检查继续覆盖旧目录。

任务失败时，「任务记录 → 错误详情」显示错误码、失败阶段和脱敏后的云存储原因；单条失败也保留对应详情。连接检查等直接操作在页面错误提示中显示同样的原因。不会回显令牌、密码或完整 SDK 请求配置。旧历史任务若只保存了通用摘要，无法补回原始错误，需要重新执行。

## 命名存储源与配置导入

可配置多份本地或云端存储源，例如：

| 存储源名称 | 类型 | 位置（仅在存储管理填写） |
| --- | --- | --- |
| 本机视频库 | 本地 | `D:\视频库` |
| OneDrive | 云存储 | `onedrive:视频存档` |
| 备用 S3 | 云存储 | `s3:bucket/archive` |

配置使用 `storage_name` 引用名称，不重复填写真实路径。改名同步更新关联配置；改变源位置会清除相关快照，等待重新刷新，不搬迁已有文件。关联中的存储源不能删除。旧 `library_dir` 在启动时幂等迁移成命名本地源，相同路径共用一个源，保留原文件和快照。

在「存储管理 → 导入 rclone 配置」直接粘贴完整、未加密的 `rclone.conf`，或选择配置文件（最多 1 MB）。支持一次导入多个已配置的远端，页面自动识别远端名称；添加云存储源时从下拉框选择远端，再在位置中填写目录，例如 `onedrive:视频存档`。无需在服务中重新进行账号授权。

导入先使用项目内 rclone 解析验证，成功后原子替换项目 TOML 旁的 `rclone.conf`（默认 `state/rclone.conf`），并自动重载子进程。失败保留原配置。导入会替换整份服务云端配置，云端快照需要重新刷新；已有视频和本地快照保留。若此前显式引用外部配置文件，导入后切换到服务自己的副本，外部文件保持不变。API 仅返回远端名，不回显配置或令牌，不将凭据提交 Git。也可在「全局设置」显式引用已有文件；默认不读取系统 rclone 配置。

下载、合并与画质检查在本地完成。云端存档先上传，再流式读取云端文件计算 SHA-256，与本地原文件比对；成功后才删除本地副本。该完整校验会产生一次额外读取流量。重试遇到同名文件时必须核验内容，一致时要求确认清理本地重复副本，不一致则停止且保留文件，不覆盖云端存档。默认不进行双向同步或 `sync` 删除。

打开云端视频会先取回独立的本地临时文件，校验成功后发布到下载目录再播放；也支持 `POST /api/configs/:id/retrieve` 显式取回。云端副本保留，本地同名内容不一致时停止。文件和文件夹始终在服务主机打开。删除会列出云端存档和本地副本，二次确认并重新核对文件身份；之后才允许排除该 BV。

存档/取回不依赖 B 站 Cookie，任务记录保存操作阶段和上传/下载进度，可取消。重启后未完成任务标为「已中断」，不会自动重复提交。RC 子进程延迟启动，只监听随机本地端口，使用随机内部凭据，随服务关闭；修改账号配置文件后可重新保存全局设置使子进程重新载入。

## Cookie 与访问方式

导入的 Cookie 原文保存在项目 TOML 的 `cookies.content`，仅保存 B 站域名；`state/cookies/` 中的执行副本可以重新生成。API 不返回 Cookie 内容。引用文件实例仅保存文件路径，在每次任务开始重新读取文件；迁移时需要另行复制该文件，或改用导入模式。浏览器实例仅保存浏览器和 profile 引用，新主机需重新登录。浏览器实例每次执行时临时导出，验证后供该任务使用，结束时删除临时凭据。TOML 与 Cookie 执行副本都是敏感文件，请保存在受当前操作系统账号保护的目录中。

Windows Chrome / Edge 的直接读取不能保证成功，可能遇到数据库锁或应用绑定加密。本次 Windows 实测返回读取/解密失败；原引用文件也缺失有效 SESSDATA 或已过期。系统因此停止刷新，未进行匿名下载。可从已登录浏览器导出 Netscape Cookie，更新同一个托管实例；绑定它的配置不需逐个修改。[yt-dlp Cookie 文档](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp)、[上游 Windows 解密问题](https://github.com/yt-dlp/yt-dlp/issues/10927)。

默认仅监听本机。跨 Windows/macOS 访问同一主机时可通过 SSH 隧道转发端口；也可以显式配置远程监听：

| 环境变量 | 默认值 / 含义 |
| --- | --- |
| `PORT` | `8765` |
| `BACKUP_HOST` | `127.0.0.1`；非本机监听必须设置至少 24 字符令牌 |
| `BACKUP_TOKEN` | 远程 API 访问令牌，页面会要求输入 |
| `BACKUP_STATE_DIR` | 项目下 `state/` |
| `BACKUP_CONFIG_FILE` | 数据目录下 `config.toml`；可指定独立的项目配置文件 |
| `BACKUP_PUBLIC_ORIGIN` | HTTPS 反向代理的精确外部来源，例如 `https://backup.example.com`，不带尾部 `/` |

远程模式请通过 HTTPS 反向代理或可信隧道传输 Cookie。浏览器不会读取访问者电脑的 Cookie 或文件系统；这些操作始终在服务主机执行。暂未集成第三方 Cookie 同步服务；托管导入和文件引用已提供自行维护入口。

## 数据与开发

```text
server/             API、调度、任务、凭据与 yt-dlp 适配器
shared/contracts.ts 前后端共享类型与输入校验
web/src/            React 界面
scripts/            固定版本下载器安装
tests/              Node.js 单元和集成测试
legacy/             最初的 Python CLI 参考备份
config.example.toml 不含真实凭据的项目配置示例
state/config.toml   项目配置：全局设置、合集、排除规则、存储源、Cookie 定义与导入内容
state/rclone.conf   独立的云存储账号配置
state/              SQLite 运行记录、快照、封面、Cookie 执行副本、运行锁（不进版本库）
bin/                官方下载器和校验记录（不进版本库）
build/              编译后的服务端
dist/               构建后的网页
```

```sh
npm test
npm run check
npm run build
npm run format
```

开发时，后端 `npm run dev`，前端 `npm run dev:web`；后端进程设置 `BACKUP_DEV=1`，允许本机 Vite 的 `http://127.0.0.1:5173` 来源。发布运行 `npm start` 使用编译后的 JavaScript，不依赖 tsx 即时编译。

## 项目配置与迁移

默认使用 `state/config.toml`，可参考 [`config.example.toml`](config.example.toml)。界面新增、编辑、删除合集/Cookie/存储源、修改全局设置和排除项都会原子写回同一份文件。手动编辑前请停止服务，重启后校验并加载；未知字段、重复 ID/名称、无效关联或不支持的版本会阻止启动，不会静默丢弃配置。运行中外部修改文件后，界面保存会提示冲突并要求重启。界面保存会重新序列化 TOML，自定义注释和排版不会保留。

相对路径以 TOML 所在目录为基准，`~` 指向服务主机用户目录。默认 `rclone.conf` 位于 TOML 旁；也可通过 `settings.rclone_config` 引用独立文件。Windows 绝对路径迁到 macOS/Linux 时需要改成本机路径，或提前使用相对路径。监听地址、端口、API 访问令牌和 HTTPS 来源仍由部署环境变量提供。

迁移到新主机时，复制 `config.toml` 和独立的 `rclone.conf`，按需调整路径、复制外部引用的 Cookie 文件或重新登录浏览器，然后启动服务、验证登录态并刷新列表。无需复制 SQLite，也能恢复全局设置、合集、存储源和排除规则；导入的 Cookie 执行文件会自动生成。配置文件包含凭据，不应提交 Git 或放进公开分发包。

SQLite 保存任务记录、列表/封面/媒体索引、下次计划执行时间、Cookie 验证状态和下载/云端完成凭证。空数据库启动会重新计时计划，不恢复旧任务；列表与封面可重新拉取，文件索引可重新扫描，但完成凭证中的画质与哈希核验信息需重新验证。希望保留这些记录时，停止服务后备份完整 `state/`；不要在 SQLite 仍写入时只拷贝单个数据库文件而忽略 WAL。下载目录与存档目录需另行备份。

详细边界见 [架构说明](docs/architecture.md)；验证记录见 [验收记录](docs/verification.md)。
