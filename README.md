# Archive Flow

一个运行在本机或自托管主机上的 Bilibili 合集自动备份工作台。Node.js + TypeScript 服务端，React 界面，SQLite 保存配置、快照和任务记录；下载由固定版本的官方 yt-dlp 独立二进制执行。新系统不依赖 Python。

最初的 Python CLI、配置、说明和 8 项原测试保存在 `legacy/`，仅作备份参考。临时 Python server 和第一版界面已删除，新服务没有调用旧 CLI。

## 启动

需要 Node.js 24、npm，以及下载/校验时使用的 ffmpeg 和 ffprobe。Windows、macOS 使用相同的项目命令：

```sh
npm ci
npm run setup:downloader
npm run build
npm start
```

打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。安装脚本从官方 release 下载对应系统的独立二进制，并校验 SHA-256。当前固定 yt-dlp `2026.08.19`；不会自动更新或切换到系统中其他版本。

ffmpeg / ffprobe 可放在 PATH 中，或在「全局设置」填写绝对路径。只打开界面、查看缓存不需要这些媒体工具。

首次启动自动导入 `legacy/config.toml` 的配置和 Cookie 文件引用，保留原下载路径，关闭所有自动计划。之后以页面保存在 SQLite 中的配置为准，不会反复覆盖。

## 使用

1. 在「Cookie 管理」添加或更新凭据实例，点击「验证登录态」。支持导入 Netscape 文件并由本机托管、引用你维护的文件、直接读取服务电脑上的浏览器。
2. 新建或编辑备份配置，填写合集链接，选择 Cookie 实例；可填存档目录、独立下载目录、日期下限。
3. 打开配置，点击「刷新 diff」。刷新在后台进行，只读合集清单与本地文件索引，不逐条查询视频画质。
4. 在 diff 中搜索、筛选、勾选或排除条目。也可通过「维护排除项」逐行添加 BV。BV 主体保留原大小写。
5. 点击下载。未勾选时处理所有待下载/需核验的中转文件；勾选后只处理所选条目。任务记录显示进度、失败原因，并支持取消排队中或执行中的任务。

| diff 状态 | 含义 |
| --- | --- |
| 待下载 | 来源中存在，本地存档与下载目录未找到同 BV 成品 |
| 已存档 | 存档目录中有同 BV 媒体文件；仅比对文件名，不重新验画质 |
| 下载目录已有 | 下载目录发现同 BV；执行时仍会按当前最高格式核验尺寸 |
| 已排除 | 手动排除，刷新和自动任务都继续遵守 |
| 日期过滤 | 发布日期不晚于配置下限，不下载 |
| 源中移除 | 上次清单有、本次清单没有；不会删除本地文件 |

合集清单缺少日期时显示「下载时核验」，不会假装已经满足日期条件。刷新失败保留旧快照及其原始时间；任务明确显示失败。修改来源、Cookie、日期或路径后会使旧 diff 失效，需要重新刷新。

## 自动执行

配置中的检查间隔为 `0` 时手动执行；自动间隔至少 5 分钟。

- 仅开启间隔：按时刷新 diff，等待人工审核。
- 同时勾选「自动检查成功后下载」：刷新成功后继续下载，遵守日期和排除项。
- 服务关闭或电脑休眠期间不执行；重启后到期计划只补一次检查，不补发积压的每个时点。
- 同一配置不重复排队。任务全局串行运行；网络和 yt-dlp 子进程异步执行，页面可继续操作。
- 取消会停止当前子进程；保留已有文件和 `.part`。失败条目可重试。重启将旧的排队/执行任务标为「已中断」，不会未经审核直接恢复旧下载。

关闭浏览器不影响自动计划，关闭 Node.js 服务会停止计划。当前版本不自动安装系统开机服务；需要持续自动备份时，请让服务随你自己的 Windows 任务计划、launchd 或进程管理器运行。

## 目录规则

默认统一根目录是 `~/Downloads/ArchiveFlow`。未指定独立下载目录的配置使用：

```text
统一下载根目录/
  配置名称/
    [YYYY-MM-DD] 标题 [BVxxxxxxxxxx].mp4
```

配置名会转换为 Windows/macOS 可用的文件夹名，命名冲突会拒绝保存。独立下载目录优先于统一根目录。改名或改路径不会搬迁旧文件。页面可复制路径或打开目录；「打开目录」打开的是服务主机上的文件管理器。

存档目录与下载目录独立。已有媒体按文件名中的 BV 索引，忽略 `.part`、侧录 JSON 和未合并的格式分片。不会删除源中移除的文件，也不会自动把新下载搬入存档目录。

## Cookie 与访问方式

托管 Cookie 放在 `state/cookies/`，仅保存 B 站域名；API 不返回 Cookie 内容。引用文件实例在每次任务开始重新读取文件。浏览器实例每次执行时临时导出，验证后供该任务使用，结束时删除临时凭据。Cookie 文件是本机敏感文件，不是加密密码库，请保存在受当前操作系统账号保护的目录中。

Windows Chrome / Edge 的直接读取不能保证成功，可能遇到数据库锁或应用绑定加密。本次 Windows 实测返回读取/解密失败；原引用文件也缺失有效 SESSDATA 或已过期。系统因此停止刷新，未进行匿名下载。可从已登录浏览器导出 Netscape Cookie，更新同一个托管实例；绑定它的配置不需逐个修改。[yt-dlp Cookie 文档](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp)、[上游 Windows 解密问题](https://github.com/yt-dlp/yt-dlp/issues/10927)。

默认仅监听本机。跨 Windows/macOS 访问同一主机时可通过 SSH 隧道转发端口；也可以显式配置远程监听：

| 环境变量 | 默认值 / 含义 |
| --- | --- |
| `PORT` | `8765` |
| `BACKUP_HOST` | `127.0.0.1`；非本机监听必须设置至少 24 字符令牌 |
| `BACKUP_TOKEN` | 远程 API 访问令牌，页面会要求输入 |
| `BACKUP_STATE_DIR` | 项目下 `state/` |
| `BACKUP_PUBLIC_ORIGIN` | HTTPS 反向代理的精确外部来源，例如 `https://backup.example.com`，不带尾部 `/` |

远程模式请通过 HTTPS 反向代理或可信隧道传输 Cookie。浏览器不会读取访问者电脑的 Cookie 或文件系统；这些操作始终在服务主机执行。暂未集成第三方 Cookie 同步服务；托管导入和文件引用已提供自行维护入口。

## 数据与开发

```text
server/             API、调度、任务、凭据与 yt-dlp 适配器
shared/contracts.ts 前后端共享类型与输入校验
web/src/            React 界面
scripts/            固定版本下载器安装
tests/              Node.js 单元和集成测试
legacy/             最初的 Python CLI 参考备份
state/              SQLite、托管 Cookie、运行锁（不进版本库）
bin/                官方下载器和校验记录（不进版本库）
build/              编译后的服务端
dist/               构建后的网页
```

```sh
npm test
npm run check
npm run build
npm run format
```

开发时，后端 `npm run dev`，前端 `npm run dev:web`；后端进程设置 `BACKUP_DEV=1`，允许本机 Vite 的 `http://127.0.0.1:5173` 来源。发布运行 `npm start` 使用编译后的 JavaScript，不依赖 tsx 即时编译。

备份系统配置：先停止服务，再备份整个 `state/`；下载目录与存档目录需另行备份。不要在 SQLite 仍写入时只拷贝单个数据库文件而忽略 WAL。

详细边界见 [架构说明](docs/architecture.md)；验证记录见 [验收记录](docs/verification.md)。
